# SMOM平台发布工具（STEP分支）

基于 **Tauri 2.0** 的 SMOM 框架发布管理桌面工具，覆盖"编译 → 配置 → 发布 → 备份 → 还原"完整链路，一站式的发布工作台与服务自发现能力，减少开发与运维人员的重复劳动。

## ✨ 功能特性

### 🚀 发布工作台

- 置顶导航首位，一站式完成发布：**欢迎 → 选择项目 → 代码源（Git / TFS）→ 服务器 → 应用配置 → 预览发布**，分步向导式操作
- 右侧实时聚合发布草稿：待发布清单与实时日志，未完成项高亮提示，预检通过后方可发布
- 复用既有发布链路（主页手动发布、生成发布、文件发布），已保存的应用配置自动带出，避免重复填写
- **新手引导**：首次安装自动弹出全屏真实表单向导，Header 提供重播入口；仅首次安装自动弹出一次，不重复打扰

### 🧩 项目发布（STEP）

分步式发布页签。顶部按界面从左到右依次为 **5 个平铺按钮**，其余功能收在「更多功能」下拉（鼠标悬停展开）；发布按服务实例串行执行「停止服务 → 用暂存程序集替换发布目录 → 启动服务」，适合希望逐步确认再发布的场景。

**平铺按钮（按界面顺序）**

1. **获取程序集** —— 按应用配置的获取方式（全部 / 当天 / 最近3天 / 日期范围 / DLL名称 / TFS / Git）把本次要发布的文件复制到本机【程序集输出路径】；TFS/Git 支持 `日期`、`变更集/commit`、`最近时间`（填天数，每次获取按当天动态计算起止）三种范围，同一配置一次运行只查询一次；勾选「生成发布日志」时在本机输出路径生成 `SMOM发布日志_时间.log`
2. **打包WPF** —— 从服务器下载 WPF 压缩包，合并本地生成目录后重新打包并更新 `Manifest.xml` 中各模块版本号（自动 +1），仅打包到本地、不上传；下载按文件计数并显示字节百分比，压缩显示「已压缩 x/N 个文件」
3. **上传程序集** —— 把本机程序集上传到各服务器【程序集暂存路径】（子目录按模块名组织）。**整包上传**：同一台服务器上本次所有模块目录合并压成一个 `_upload_batch.zip`，每台服务器只上传 1 个文件、只解压 1 次，落盘仍是 `<程序集暂存路径>/<模块名>/…`；**上传前先清空**本批次所有模块目录（本地已删除的旧文件不会被【发布】带走，清空在本地打包成功后执行）；上传前探测服务端解压命令（`unzip` / `Expand-Archive`），不支持或整包失败自动回退逐文件上传；两种方式都保留本地修改时间，供【核对程序集】比对
4. **核对程序集** —— 以本机为准逐文件比对各服务器暂存程序集的修改时间，按「服务器 + 模块目录」一行展示本地文件数、服务器文件数、缺失、时间不一致、服务器多出与差异合计（无差异显示「一致」）；默认开启「仅看差异」，展开行可看逐文件明细（含本地/服务器时间）；时间按 UTC 比对、容差 ±2 秒（zip 时间戳仅 2 秒精度），服务器多出的残留旧文件同样计入差异，重新【上传程序集】清空重建即可消除
5. **发布** —— 每个服务实例固定三步：**停止服务 → 用暂存程序集替换发布目录 → 启动服务**；实例一旦开始就完整执行三步（不会留下停了却没替换的服务），未开始的实例跳过；每个实例向 `<程序集暂存路径>/发布日志.log` 写入「发布开始 / 发布成功 / 发布失败（原因：关闭服务、替换程序集、启动服务或部署环境不匹配）」

**「更多功能」下拉（悬停展开，按界面顺序）**

- **查看服务端程序集** —— 列出各服务器【程序集暂存路径】下各模块目录的**最新文件**与**最旧文件**（文件名 + 修改时间）
- **查看本机程序集** —— 列出本机【程序集输出路径】下各模块目录的**最新文件**与**最旧文件**（文件名 + 修改时间），与服务端对照即可判断程序集新旧
- **备份** —— 发布前把各服务目录整目录拷贝到服务器【服务备份路径】，文件夹按年月日时分命名（同名已存在则先清空内容再备份）；内部子文件夹默认用目录名、仅重名时拼上级目录区分
- **备份管理** —— 查看每台服务器备份目录中前 10 个备份文件夹及服务明细，支持对指定备份**删除**与**恢复**（恢复自动执行「停止服务 → 替换文件 → 启动服务」，WpfClient 替换备份中全部文件、其余服务仅替换一级目录 DLL）
- **服务管理** —— 查看各服务（Windows 服务 / Docker 容器）运行状态，按「服务器卡片 → 服务行」分组展示（卡片可折叠、支持全部展开/折叠），支持单服务与整台服务器两级勾选及批量的停止、启动、重启，完成后自动刷新

**通用机制**

- **最新产物前置检查**：获取程序集、打包WPF、上传程序集前自动检查本机程序集目录是否有「最新时间阈值」内（默认 10 分钟，可在发布信息卡 1~1440 分钟调整）修改的文件，没有则列出各目录最新修改时间，确认后才继续，防止拿旧产物发布
- **实时进度**：下载按文件计数 + 字节百分比、上传按字节百分比、压缩按文件数，进度都在同一行日志刷新，不刷屏
- **立即停止**：日志卡右侧「停止」立即生效——后端重试、等待轮询、SSH 建连阶段秒级中断，后端重试实时上屏；对话框（服务管理、程序集信息、服务备份、恢复备份）内也有停止按钮
- **发布顺序可配**：默认 WebApiHost → WebClient → ScheduleServer → WpfClient → SpcMonitor，设置页可上移/下移调整；备份、上传、发布、服务状态查询与「发布信息」卡的应用类型列表统一按该顺序处理
- **启停等待超时可配**：服务启动、停止确认默认各等 20 秒（设置页 5~300 秒可调），异常服务不会再把后续实例长时间堵住
- **项目记忆**：发布项目与环境均在发布信息卡直接选择（Dev / Uat / Pro / Other），记住上次选择、下次打开自动恢复（项目被删除时回退默认项目）；切换环境按「项目 + 环境」即时刷新应用配置，切走再切回页签保持页面状态、不重新查询
- **操作留痕与回查**：备份、恢复备份、上传程序集、发布完成后自动在服务器对应目录追加一行操作日志（备份/恢复在【服务备份路径】、上传/发布在【程序集暂存路径】下，内容为时间 + 操作信息），配合服务器管理页的【查看日志】【下载日志】随时回查
- 页面内置「功能说明」帮助文档，第一次使用照着快速上手即可

### 📦 项目发布（发布平台主页）

- 四大入口：**编译项目**（MSBuild 构建）、**获取程序集**（DLL 复制）、**手动发布**、**定时发布**
- Dev / Uat / Pro / Other 多环境一键切换，项目配置自动带出
- 发布前备份（可配置远端备份路径）、异步上传开关
- 实时日志面板，支持一键清空，发布日志仅保留最新

### 🗂 项目管理

- SLN 解决方案解析，自动获取模块编译输出路径（Release / Debug、新旧版本）
- MSBuild 一键构建（支持强制重新生成）、DLL 批量复制
- 程序集名称（AssemblyName）查询、Manifest 模块版本号自动升级（末位自增）
- 定时发布任务管理：创建 / 取消 / 查看待执行任务
- 应用配置 TFS 变更集起止值修改

### ⚙️ 应用配置

- 按项目管理五大部署模块：**WebApiHost、ScheduleServer（调度）、WebClient、WpfClient、SpcMonitor**
- 每个模块可绑定多台服务器，分别配置服务标识与发布路径（WpfClient 同样支持多服务器发布）；选择服务器后自动带出服务器上预配置的默认服务标识 / 发布路径
- **项目 + 环境组合唯一**：同一项目下 Dev / Uat / Pro / Other 各环境独立一份配置；「复制新增」整份复制到目标环境，环境已占用时明确报错
- 获取dll方式：全部 / 当天 / 最近3天 / 日期范围 / DLL名称 / TFS / Git；TFS 与 Git 下可按**日期**、**变更集**、**最近时间**（按天录入，如 3 表示最近 3 天，每次获取时动态计算范围）查询
- 与发布工作台、主页发布、文件发布、备份还原全链路联动

### 📄 文件发布

- 手动选择本地文件 / 目录，直接发布到指定服务器
- 发布前自动备份，支持远程还原

### 🖥 服务器管理

- SSH 服务器纳管：连接配置、所属项目筛选（支持一键清空；所属项目可选「全部」，该服务器共享给所有项目选用）
- 远程命令执行、文件上传下载、Windows 服务启停
- SSH MCP 配置上传，供 AI 编码助手（如 ZCode）直连远程服务器操作
- **服务自发现**：SSH 连接按 systemd / Docker / 进程三条链路自动发现已部署服务路径，按名称自动映射到应用配置各模块；确认导入后直接生成服务条目，一键认领纳管服务器，无法识别模块的服务明确标注跳过
- **默认服务标识 / 发布路径**：每台服务器可配置多组「服务类型 + 服务标识 + 发布路径」（上限 10 组），应用配置选择服务器后按服务类型自动带出，免重复手工录入；【识别服务】按钮一键扫描远端已部署服务并只追加生成服务组（原有配置不动、重复自动跳过），Docker 容器多挂载时按启发式评分优先取应用目录而非字体等系统挂载
- **文件管理路径**：每台服务器可配置多组管理路径（上限 10 组），【识别文件夹】一键探测各非 WPF 服务路径下的 `logs` 与 WebClient 服务路径下的 `wwwroot/Templates`，存在即加入候选
- **文件管理**：操作列弹窗直达——多路径多文件上传（逐行进度、可终止）；存在文件可选跳过 / 覆盖 / 保留最新（默认保留最新，选择全局记忆）；浏览指定路径一级文件/文件夹（列头排序、关键词过滤、批量下载与删除）；上传 / 下载 / 删除 / 读取目录均走独立终止标记，不与发布「停止」互相打断
- **服务器日志**：STEP 发布流程会在备份/恢复/上传/发布后自动向服务器写入操作日志；操作列【查看日志】打开日志窗口，以页签展示「备份 / 恢复 / 上传 / 发布」四类日志（页签懒加载、首次激活才读取，「刷新」重读），窗口内可直接下载当前页签完整日志；【下载日志】下拉可把指定日志另存到本机；日志文件分别位于服务器的服务备份路径、程序集暂存路径下（Windows 走 PowerShell `Get-Content -Tail`、Docker/Linux 走 `tail`，中文路径与内容不乱码）
- 配套发现前缀管理（设置页），统一约定服务路径扫描规则

- 获取最新代码、签出 / 签入、撤销本地修改

- 查询记录一键生成发布日志

### 💾 备份记录

- 发布前备份与还原全流程留痕

- 备份导入导出

### 🧊 图标

- 三套图标库一览：SMOM 自绘图标（smom-icon）、FontAwesome（fa）、Element Plus（ele-），按名称模糊搜索并高亮命中片段，分页加载
- 预览设置：尺寸滑块、颜色下拉、复制格式（组件用法 / 类名 / 路由配置），点击图标即复制
- Element Plus 语义色与文字色色板，点击直接应用；附 SvgIcon 属性表与用法示例

### 🛠 设置

- 开机自启动（驻留系统托盘）
- **启动默认菜单**：发布工作台 / 项目发布 / 项目发布(STEP)，保存后下次启动生效（配置在设置页「窗口」分区）
- 重试策略：服务启停重试次数 / 间隔、本地命令重试、文件复制重试、上传重试
- **服务启停等待超时**：启动等待、停止等待分别配置（5~300 秒，默认各 20 秒），超时视为该次启停失败
- **发布顺序**：上移/下移调整 5 个模块的处理次序（默认 WebApiHost → WebClient → ScheduleServer → WpfClient → SpcMonitor），备份 / 上传 / 发布 / 服务状态查询统一生效
- 底部常驻「保存 / 取消保存」按钮栏：配置有改动才可点保存，并提示「当前配置未保存」；取消保存恢复为已保存的配置
- 服务发现前缀管理
- 界面语言切换（简体中文 / English / 繁體中文）、四种布局主题

### ℹ️ 关于与自动更新

- 独立"关于"页面：显示当前版本号，支持手动检查更新

### 🧊 桌面特性

- 系统托盘驻留、关闭窗口行为可配（最小化到托盘 / 退出程序）、单实例锁

## 🚀 快速开始（开发环境）

要求 Node >= 16、npm >= 7，以及 Rust stable 工具链。

```bash
# 克隆项目
git clone https://github.com/nickynull/publish-tools.git

# 进入项目
cd publish-tools

# 安装依赖
npm install

# 开发调试
npm run tauri dev

# 打包桌面应用（输出到 src-tauri/target/release/）
npm run tauri build
```

## 📥 安装与更新

前往 [Releases](https://github.com/nickynull/publish-tools/releases) 下载最新版本安装包，安装即用。应用启动时会自动检查更新，也可在"关于"页面手动检查，升级弹窗会展示对应版本的 Release 说明并支持一键下载安装。
