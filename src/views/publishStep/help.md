## 🚀 一、快速上手（第一次使用照着做）

**第 0 步：一次性基础配置**（配置过可跳过，都在左侧菜单）

1. **服务器管理**：添加服务器（IP、账号、密码、系统类型）。如需备份服务，配置【服务备份路径】；如需上传程序集，配置【程序集暂存路径】。操作列的【查看日志】【下载日志】可选择备份 / 恢复 / 上传 / 发布，查看对应日志的最新 100 行或下载到本机（日志文件分别位于服务备份路径、程序集暂存路径下，由本页的备份 / 恢复 / 上传 / 发布操作自动写入，见「五、日志信息区域」）。
2. **TFS / Git**：配置版本库连接（含本地源码路径），获取程序集时要用。
3. **项目管理**：添加项目并设置【程序集输出路径】（本机存放待发布文件的地方）；解决方案路径在应用配置中维护（STEP 编译解决方案用）。
4. **应用配置**：选择项目与环境（Dev/Uat/Pro/Other），配置各模块的客户端生成路径、服务器、服务标识（Windows 服务名或 Docker 容器名）与发布路径。

**日常发布五步**（都在顶部平铺按钮区，按界面从左到右依次点击）：

0. 【获取最新代码】（可选）：按应用配置的获取方式（TFS/Git）拉取仓库最新代码。
1. 【编译解决方案】（可选）：用 MSBuild 一次编译整个解决方案（`.sln`），解决方案路径在发布信息卡配置（实时落库），编译参数点【编译配置】设置。
2. 【获取程序集】：根据 TFS/Git 变更或 DLL 名称，把要发布的 DLL 复制到本机程序集输出路径。
3. 【打包WPF】：从服务器下载 WPF 压缩包，合并本地最新文件后重新打包并更新版本号。
4. 【上传程序集】：把本机程序集上传到各服务器的程序集暂存路径。
5. 【发布】：逐个服务「停止服务 → 用暂存程序集替换发布目录 → 启动服务」。

> 💡 获取程序集到发布四步可用顶部【一键发布】按钮（可在设置页「项目发布(STEP) → 一键发布按钮」中显示/隐藏）一次完成（依次执行：获取程序集 → 打包WPF → 上传程序集 → 发布，任一步失败即中止，**不含获取最新代码与编译解决方案**）；如需发布前留底，先执行「更多功能 → 备份」再发布。
>
> 💡 设置页「项目发布(STEP) → 一步获取程序集」开启后，顶部不再显示【打包WPF】按钮，其操作在【获取程序集】成功后自动执行。

## 📖 三、各按钮详细说明（按界面顺序）

### 📥 获取最新代码（平铺第 1 个）

- **作用**：按应用配置的[获取dll方式]（TFS `tf get` / Git `git pull --ff-only`）把仓库最新代码拉取到本机源码目录，保证后续编译用的是最新代码。
- **直接执行**：直接点击本按钮**不受**[拉取最新代码]开关控制（该开关只控制【编译解决方案】的前置拉取，见发布信息卡）。
- **保护**：Git 分支与应用配置记录不一致时跳过不拉取；TFS 拉取出现冲突即中止并列出冲突文件；缺 TFS/Git 配置时提示原因、按未成功返回。

### 🛠 编译解决方案（平铺第 2 个）

- **作用**：用 MSBuild **一次编译整个解决方案（`.sln`）**，替代主页「编译项目」那种逐个 csproj 编译的方式；编译产物直接落在各项目自身的输出目录，供后续【获取程序集】提取。
- **与主页【编译项目】的区别**：只调用一次 `msbuild <sln>`（`/restore /m /clp:ErrorsOnly` + `Configuration` + `Platform`），不再逐个删除并编译各模块生成目录，也不会因为某个模块路径配置错误而中断。
- **前置拉取**：发布信息卡「拉取最新代码」开关开启时（缺省开启），编译前先按应用配置获取一遍最新代码，拉取失败即中止编译。
- **参数来源**（发布信息卡「解决方案」一行）：
  - **解决方案路径**：显示应用配置的「解决方案」路径，在发布信息卡点【选择】调整后**实时落库**（存应用配置，该项目该环境生效）。
  - **生成模式**：Release / Debug（默认取应用配置的生成模式）。
  - **平台**：Any CPU / x64 / x86（需与解决方案配置里的平台一致）。
  - **方式**：重新生成（Rebuild，先清理再编译，耗时更长）/ 增量生成（Build，默认沿用应用配置的「是否重新生成」）。
  - **MSBuild 路径**：取应用配置的 `MSBuild路径`，为空时自动探测（`vswhere`）。
  - 生成模式、平台、方式收进发布信息卡「编译配置」下拉按钮（解决方案下方），按 **项目 + 环境** 记忆在本机。
- **执行前确认**：弹窗列出解决方案、生成模式/平台/方式，确认后才开始编译。
- **日志**：先打印解决方案、模式、平台、方式与 MSBuild 来源，结束后打印耗时；失败逐行输出 error（最多 60 行），成功记一条绿色日志。
- **停止**：编译中可点日志卡右侧【停止】，会立即结束 MSBuild 进程（不会残留编译进程）。
- 本步骤不纳入【一键发布】链路，需要时单独点击。

### 📥 获取程序集（平铺第 4 个）

- **作用**：确定本次要发布的文件清单，并把文件复制到本机【程序集输出路径】。
- **获取方式**（应用配置中设置）：
  - TFS：按变更集 / 日期 / 最近时间查历史
  - Git：按提交 / 日期 / 最近时间查历史
  - DLL名称：按名称匹配
  - 当天 / 最近3天 / 日期范围：按文件修改时间筛选
  - 全部：整目录复制
- **获取范围**：TFS/Git 的三种模式——**日期**（手填起止时间）、**变更集/commit**（手填起止号）、**最近时间**（填天数，如 3 表示最近 3 天；每次点击获取时按当天动态计算起止范围，不用手改配置）。
- **日志**：会显示获取方式、获取范围（如「日期：2026-10-01 00:00:00 ~ 至今」、「最近时间：最近 3 天（… ~ …，每次获取动态计算）」）、每个模块的复制进度（单行刷新）。同一 TFS/Git 配置一次运行只查询一次，重复模块会提示「已复用查询结果」。
- 若应用配置勾选了【生成发布日志】，会在程序集输出路径生成 `SMOM发布日志_时间.log`。

### 📦 打包WPF（平铺第 5 个）

- **作用**：为 WpfClient 生成发布包，仅打包到本地不上传。产出目录按服务器区分：`<程序集输出路径>/WpfClient/packOutput/<服务器id>/`，多服务器逐台打包互不覆盖；【上传程序集】【核对程序集】同样按服务器 id 读取对应产出目录。
- **流程**（4 步）：准备本地打包目录 → 从服务器下载远程 zip → 解压、合并本地生成目录、重新打包、更新 Manifest.xml 中各模块版本号（自动+1）→ 完成。
- **进度**：下载阶段按文件计数（`第 n/N 个`）并显示已传输字节百分比；压缩阶段显示「已压缩 x/N 个文件」；都在同一行日志实时刷新。
- 设置页「一步获取程序集」开启后本按钮隐藏，操作随【获取程序集】成功后自动执行；应用配置未配置/移除 WpfClient（不发布 WPF）时本按钮同样隐藏。

### ⚡ 一键发布（平铺第 3 个，可在设置中隐藏）

- **作用**：把【获取程序集】【打包WPF】【上传程序集】【发布】合成一步，确认后依次自动执行，任一步失败即中止；**不含获取最新代码与编译解决方案**，需要时单独点击。
- **流程**：开始前一次性确认（提示建议先【备份】），并做一次获取前的最新产物检查；随后 获取程序集 →（按需）打包WPF → 上传程序集 → 发布，各步骤间打印分割线，每步成功后记录结果日志。
- **打包WPF 只执行一次**：「一步获取程序集」开启时随获取程序集执行；未开启时作为链路中的独立步骤执行。未发布 WpfClient（应用配置未配置或已移除）时不打包、直接跳过该步。
- **停止**：执行中可随时点【停止】，对链路中所有步骤生效；某步失败或停止后，后续步骤不再执行（已完成步骤的远端状态与逐项执行一致）。
- **loading**：执行中「更多功能」卡片显示加载动画，状态文字随当前步骤切换（获取中/打包中/上传中/发布中）。

### 📤 上传程序集（平铺第 6 个）

- **作用**：把本机程序集输出路径的内容上传到各服务器的【程序集暂存路径】（子目录按模块名组织）。
- **流程**（6 步）：校验本地目录 → 创建服务器暂存目录 → 探测服务器解压命令 → 本地打包 → **清空服务器暂存目录** → 上传整包并在服务端解压（带实时进度）。
- **整包上传**：同一台服务器上本次要发布的**所有模块目录合并压缩成一个包**（`_upload_batch.zip`），每台服务器只上传 1 个文件、只解压 1 次，服务端落盘仍是 `<程序集暂存路径>/<模块名>/…`；模块组合相同的多台服务器复用同一个包，整轮只压缩一次。日志按服务器分段输出（服务器行 + 参与模块行）。
- **清空规则**：上传前会把本批次涉及的**所有模块**目录 `<程序集暂存路径>/<模块名>` 整个删除并重建为空目录（一条远程命令批量处理，原有条目数会写进日志），确保服务器上的程序集与本次本地内容完全一致；本地已删除的旧文件因此不会在【发布】时被覆盖到服务内。清空发生在本地打包成功之后，打包失败不会动服务器上的程序集。
- **上传方式**：
  - 服务器具备解压命令时走整包上传：本地把全部模块压成一个 zip，上传后在服务端一次性解压到暂存路径根目录（包内顶层目录即模块名），上传时显示字节百分比进度。
  - 服务端解压依赖 Linux 的 unzip 或 Windows 的 PowerShell（Expand-Archive）：上传前会先探测该命令，不可用则整台服务器回退为逐文件上传（不会白白压缩）；整包上传/解压中途失败也会自动回退为逐模块逐文件上传，不影响结果。
- **文件时间**：两种上传方式都保留本地文件修改时间，【核对程序集】可直接比对。

### ✅ 核对程序集（平铺第 7 个）

- **作用**：上传后核对各服务器上的程序集是否与本地一致。以**本机程序集**为准，逐文件比对各服务器【程序集暂存路径】对应模块目录中文件的修改时间。
- **差异项**（以本机为准）：
  - 服务器缺失文件：本地有、服务器无。
  - 时间不一致：同名文件双方修改时间相差超过 2 秒（打包上传路径的 zip 时间戳只有 2 秒精度，奇数秒文件解压后可能差 1 秒，属正常现象，已在比对中放宽容差；统一按 UTC 比对，不受服务器时区影响）。
  - 服务器多出的文件：本地已删除、服务器暂存目录仍存在。**同样视为差异**，计入差异合计（这类文件若不清掉，发布时会被一起覆盖到服务目录，可用【上传程序集】清空重建来消除）。
- **展示**：每个服务器每个模块目录一行（双方文件数、缺失数、时间不一致数、服务器多出数、差异合计），默认开启「仅看差异」过滤一致行；展开行可查看逐文件差异明细（含本地/服务器时间，服务器多出的文件显示其服务器上的修改时间，本地侧标「本地无此文件」）。
- **提示**：历史上传的文件时间仍是上传时刻，会报时间不一致——重新执行【上传程序集】即可校正（现在上传会保留本地修改时间）。

### 🚢 发布（平铺第 8 个）

- **作用**：把暂存路径的程序集发布到各服务实例。每个实例固定三步：**停止服务 → 替换程序集（暂存目录/模块 → 发布路径）→ 启动服务**。
- 实例一旦开始执行就会完整执行三步（避免留下停了却没替换的服务）；未开始的实例会被跳过。
- **发布顺序**：按设置页「发布顺序」逐个实例处理，默认 `WebApiHost → WebClient → ScheduleServer → WpfClient → SpcMonitor`；备份、上传程序集、服务状态查询使用同一顺序。
- **启停等待超时**：启动、停止后轮询确认状态的最长等待在设置页配置（默认各 20 秒），超时即判定该实例失败并中止本次发布，不会长时间卡住。
- **发布日志**：每个实例向 `<程序集暂存路径>/发布日志.log` 写入「发布开始 / 发布成功 / 发布失败（原因）」，失败原因会写明是关闭服务、替换程序集、启动服务还是部署环境不匹配，可在服务器管理页【查看日志】直接回查。
- 所有日志输出到总体日志；替换失败会给出恢复提示。

### 👀 查看服务端程序集 / 查看本机程序集（更多功能第 1、2 个）

- 分别列出服务器【程序集暂存路径】与本机【程序集输出路径】下各模块目录中**最新文件**与**最旧文件**的文件名和修改时间，用于核对程序集是否为新。

### 💾 备份（更多功能第 3 个）

- **作用**：发布前把服务目录整目录拷贝到服务器【服务备份路径】下，留底以便回退。
- **规则**：
  - 备份文件夹按**年月日时分**命名（如 `202610242159`）。
  - 已存在则先清空内容再备份（防止残留已删除文件）。
  - 内部子文件夹默认用目录名，仅重名时拼接上级目录区分（如服务路径 `x/y/A` 备份为 `202610242159/y_A`）。
- **流程**（3 步）：准备备份文件夹（创建+清空）→ 逐个服务整目录拷贝 → 更新备份文件夹修改时间为当前时间（便于识别备份时间）。

### 🗂 备份管理（更多功能第 4 个）

- **展示内容**：每台服务器备份目录中**按名称降序前 10 个**备份文件夹，包含文件夹名称、备份时间（文件夹修改时间）、内部备份的服务明细。
- 每行提供两个操作：
  - **恢复**：
    - 选择该日期备份下的服务文件夹与要恢复的服务，可开启「自动匹配」按目录名联动。
    - 确定后执行：停止服务 → 替换文件 → 启动服务。
    - WpfClient 替换备份中的全部文件，其余服务仅替换一级目录中的 DLL。
  - **删除**：将该备份文件夹及其内容从服务器上删除；需二次确认，删除后不可恢复。
- 没有数据？请先执行【备份】或在服务器管理中配置【服务备份路径】。

### 🖥 服务管理（更多功能第 5 个）

- 列出应用配置中所有带服务标识的实例的运行状态（Windows 服务 / Docker 容器）。
- 按**服务器**分组以卡片展示，服务器内所有服务同级平铺（每行显示应用类型、服务标识、状态与操作）；服务器卡片头显示该服务器「运行中 X/Y」，存在未知状态时追加「未知 n」。
- **服务器卡片可折叠**：点服务器卡片头（或右侧箭头图标）折叠/展开整台服务器，折叠后仍显示「运行中 X/Y」汇总；顶部【全部展开】【全部折叠】可一键切换，重新打开对话框时默认全展开。
- 查询状态时列表区显示加载中提示并保留占位高度；对话框内容区最小高度 600px，数据少时不会忽高忽低。
- 支持**单行**与**批量**的停止、启动、重启（重启=先停止等完全停止再启动）。
- 操作方式：勾选服务或整台服务器（组头支持半选态）后点顶部批量按钮，或直接点行内按钮；操作前有确认框，完成后自动刷新状态并清空勾选。
- 操作日志记录在「总体日志」；状态未知（未找到服务/容器）的行不可操作、不可勾选，组内无可操作服务时组头勾选框禁用。

## 📋 四、发布信息区域

- **项目 / 环境选择**：项目与环境都在发布信息卡直接选择，决定本页所有功能操作哪套配置。两者都按项目记忆在本地，下次打开自动恢复上次的选择（上次选的项目被删除时回退默认项目）；切换环境按「项目 + 环境」即时刷新应用配置；切到其它页签再回来不会重新查询，保持页面状态。
- **程序集输出路径**：来自项目管理配置，点击可打开本机目录。
- **解决方案**（发布环境下方，两行）：
  - 第一行「解决方案」：显示应用配置的「解决方案」路径，点【选择】调整后**实时落库**（存应用配置 t_app_config.solution_path，项目+环境生效；点路径可打开所在目录）。
- **编译配置行**（解决方案下方）：点【编译配置】下拉按钮设置生成模式（Release / Debug）、平台（Any CPU / x64 / x86）、方式（重新生成 / 增量生成），按「项目 + 环境」记忆在本机（localStorage），切换项目/环境自动切换显示；同行右侧「拉取最新代码」开关控制【编译解决方案】编译前是否先按应用配置获取一遍最新代码（缺省开启，调整实时落库），直接点击顶部【获取最新代码】按钮不受此开关控制。
  - 这些都是顶部【编译解决方案】按钮使用的参数，不影响主页【编译项目】。
- **与【修改】（应用配置弹窗）联动**：应用配置弹窗同样提供「解决方案」路径与「拉取最新代码」开关（均可改），保存后发布信息卡即时同步显示。
- **发布信息(N)**：卡片标题中的数字为当前应用配置的应用类型模块数量，增删模块后实时变化。
- **最新时间阈值**：获取 / 打包WPF / 上传程序集前检查本机程序集目录是否有该分钟数内修改的新文件（默认 10 分钟），没有时确认后才继续。
- **获取方式 / 获取范围**：来自应用配置，决定获取程序集的行为；TFS/Git 方式会显示配置的范围（日期/变更集/commit）。
- **生成发布日志**：开启后获取程序集时生成日志文件，生成方式四种：
  - **默认**：逐变更集列出用户/日期/DLL/更新内容（给自己或运维核对）。
  - **仅发布内容**：只有更新说明清单（适合发给业务/客户）。
  - **按日期**：同一天的变更归组并汇总 DLL。
  - **按用户**：按提交人归组并汇总 DLL。

  「生成信息包含」勾选项决定各方式输出哪些字段；勾选 DLL 文件时需要到本机源码解析 csproj，会慢一些。
- **修改应用配置**：打开应用配置弹窗编辑当前配置；弹窗内切换项目管理会自动加载对应项目的已有配置。改完保存后发布信息自动刷新。
- **刷新|重置**：重新读取默认项目与环境配置。

## 📜 五、日志信息区域与停止按钮

- **总体日志**：所有功能的执行过程按时间顺序记录在**同一个日志区**（不再分标签页），日志正文会标明模块、服务器与服务实例；日志不会在每次执行前自动清空，跨操作可持续回看。
- **行号**：每行日志前显示行号，可通过标题栏「行号」开关显示/隐藏（配置保存在本机浏览器，默认开）；行号按最大行号的位数对齐。
- **行数上限**：日志默认保留最近 **1000** 行，超出后自动清理最旧的行；上限可在「清空日志」按钮旁调整（10 ~ 100000），配置保存在本机浏览器（localStorage），下次打开自动恢复。
- **服务器操作日志**：备份 / 恢复备份 / 上传程序集 / 发布完成后，自动在服务器对应目录的日志文件里**追加一行**（时间 + 操作信息）：备份、恢复记录时间文件夹、服务文件夹与恢复目标，写在【服务备份路径】下的 `备份日志.log`、`恢复日志.log`；上传记录文件个数（WPF 为文件清单与 zip 版本）、发布记录模块、服务标识与发布路径，写在【程序集暂存路径】下的 `上传日志.log`、`发布日志.log`。写入失败只在本页告警，不影响操作本身；可在服务器管理页【查看日志】【下载日志】回查。
- **单行进度**：复制/上传等循环任务在同一行刷新「n/N」，不刷屏。
- **传输进度**：下载、上传、压缩都会在同一行日志实时刷新进度（下载按文件计数 + 字节百分比，上传按字节百分比，压缩按文件数），无需另开窗口查看。
- **停止按钮**（日志卡标题右侧红色按钮）：向正在执行的功能发出停止请求，**立即生效**：
  - 重试之间、等待轮询中、连接服务器的建连阶段都会秒级中断，不再傻等。
  - 单个正在进行中的命令本体（如一个正在上传的文件）无法掐断，会在该命令结束后停止后续操作。
- **对话框停止**：服务管理、程序集信息、服务备份、恢复备份等对话框内也有「停止」按钮，停止后返回已获取的部分结果并提示已获取条数。
- 日志中的红色为失败、黄色为警告（含后端重试提示「[重试] 第 n/N 次失败」）、绿色为成功。

## ❓ 六、常见问题

- **查看服务备份没有数据？**先在服务器管理配置【服务备份路径】并执行一次【备份】；也可直接读取服务器上已有的备份目录（按名称降序前 10 个）。
- **获取程序集很慢？**TFS/Git 方式要查询版本历史并到本机源码解析 csproj 生成 DLL 清单；生成发布日志勾选了「DLL文件」也会增加解析耗时。同一配置在本次运行内会复用查询结果。
- **SMOM发布日志文件在哪？**在程序集输出路径下，文件名 `SMOM发布日志_年月日时分秒.log`，每次生成会先清理旧的。
- **服务器上的操作日志在哪？**备份 / 恢复在【服务备份路径】下、上传 / 发布在【程序集暂存路径】下，各有一个日志文件（备份日志 / 恢复日志 / 上传日志 / 发布日志），本页每次执行对应操作都会追加一行；服务器管理页操作列【查看日志】【下载日志】可直接回查。
- **发布失败提示「服务已停止且未完成替换」？**按日志提示处理：可重新【上传程序集】后再【发布】，或手动启动服务。
- **核对程序集全报「时间不一致」？**历史上传的文件修改时间是上传时刻（上传时未保留本地时间），重新执行【上传程序集】后再核对即可；新上传的文件已自动保留本地修改时间（比对容差 ±2 秒）。
- **核对程序集报「服务器多出」/ 发布后服务里出现已删除的旧文件？**说明服务器暂存目录残留了本地已删除的文件（旧版本上传只覆盖不清空）。现在【上传程序集】会先清空暂存模块目录再上传，重新执行一次即可消除；清空后该行应显示「一致」。
- **打包上传后服务器文件时间比本机少 1 秒 / 之前曾整体差 8 小时？**zip 内记录的时间只有 2 秒精度且不带时区，解压端按服务器时区解释：奇数秒文件解压后最多差 1 秒，属正常现象，【核对程序集】已按 ±2 秒容差比对。WpfClient 走逐文件上传，时间完全一致。
- **功能按钮置灰/提示有功能在执行？**同一时间只允许一个功能运行，等待当前功能完成或点停止。
